# Project ownership and scope

This is the owner's personal portfolio project, built through many hours of handwritten backend, frontend, and design work. It demonstrates their own coding and design ability. Preserve that authorship and character.

- Default to minor, targeted adjustments needed for readability, correct operation, and deployment.
- Preserve the existing architecture, technology stack, design, coding style, and handwritten implementations.
- Do not rewrite, broadly refactor, redesign, replace frameworks, add features, or perform unrelated cleanup unless the owner explicitly requests that scope.
- For a bug fix, make the smallest practical change that addresses the demonstrated problem. Keep validation proportional and preserve existing work.
- If a necessary change would go beyond minor adjustments, explain the concrete need and proposed scope and get the owner's explicit agreement before implementing it.
- Explain what changed and why, and clearly identify any remaining limitation.
- The owner's preference to avoid Ruby for future projects does not authorize migrating this project's Rails backend.
